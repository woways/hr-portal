1. Introduction & Purpose

This document is the complete Product Requirements Document (PRD) for the WOWAYS HR Portal, an enterprise Human Resource Management System. It fully specifies both applications that make up the product — the HR Admin Dashboard and the Employee Self-Service Portal — describing every module, its purpose, its workflows, the data it reads and writes, and how the two applications interact through a shared backend.

The purpose of this document is to serve as a single, authoritative reference for stakeholders, developers, QA and future maintainers: what the product does, how it is structured, and the requirements each part fulfils.

2. Product Vision & Business Context

WOWAYS operates across six departments — Sales, Operations, Marketing, Hiring, Technology and Business Growth. Managing employee data, attendance, leave, payroll, recruitment and performance across these teams using spreadsheets and disconnected tools is error-prone and slow. The HR Portal replaces that with a unified, real-time digital system.

Vision: A single source of truth for the entire employee lifecycle — from a candidate applying, through onboarding, daily attendance, leave, payroll and performance, to eventual exit — accessible to HR for management and to employees for self-service, with every change synchronised instantly across both experiences.

Key business objectives

ObjectiveHow the product delivers it
Centralise all HR dataOne Firestore database holds employees, attendance, leave, payroll, goals, recruitment and more.
Reduce HR workloadEmployees self-serve profile updates, leave applications, payslip downloads and document uploads.
Real-time accuracyApprovals, goals and announcements propagate instantly to employees via live listeners.
Compliance & record-keepingStructured capture of statutory data (PAN, Aadhar, PF, UAN, bank) with controlled access.
Speed & experienceCache-first loading and skeleton states for a fast, modern feel.

3. System Overview — The Two-Dashboard Model

The product is delivered as two separate web applications that share one Firebase project (database, storage and authentication). This separation keeps each experience focused while guaranteeing consistency, because both apps operate on the same underlying data.

ApplicationAudiencePrimary function
HR Admin DashboardHR administratorsManage the entire workforce and all HR operations.
Employee Self-Service PortalIndividual employeesView and manage only their own information and requests.
Important nuance: the employee experience exists in two forms that behave identically — a standalone employee app (woways-employee.web.app) and an employee route inside the HR app (/employee/dashboard). Both are backed by the same data, so an employee sees the same profile, leave and notifications regardless of which they use.

Architectural principles

  • Client-centric: With static export there is no application server — all business logic runs client-side and talks directly to Firebase, with security enforced by Firestore/Storage rules.
  • Shared backend: Both apps point at the same project, so no synchronisation service is needed — Firestore is the integration layer.
  • Real-time by default: Collaboration-sensitive data (leave, goals, notifications, sidebar identity) uses live listeners.

6. Authentication & Account Provisioning

  1. Account creation: HR adds an employee in the directory. The system assigns a sequential employee ID (EMP001, EMP002…), creates a Firebase Auth account with generated credentials, and writes a users/{uid} document linking the Auth UID to that employee ID.
  2. Login: Users sign in with email/password; the session persists locally across refreshes.
  3. Identity resolution: On load, the app resolves the employee's Firestore record primarily by email lookup (where("email","==",user.email)) — the most reliable link to the actual document — falling back to users/{uid}.employeeId.
  4. Account removal: If an employee's record is deleted, the next session detects the missing document and signs the user out with an "account removed" reason.
  5. Password management: Employees can change their password (with re-authentication) or trigger a reset email.

7. HR Admin Dashboard — Complete Module Specification

7.1 Dashboard / Overview /dashboard

The landing screen giving HR an at-a-glance view of the organisation. It loads cache-first with skeleton loaders, then refreshes from Firestore.

  • Welcome header — greeting with current date and a live-updating clock.
  • Employee overview cards — Total Employees, Total Interns, Active, On Probation, On Leave, Exited.
  • Attendance overview (today) — Present, Absent, Late Logins, Half-Day, Average Working Hours.
  • Leave summary — Pending, Approved, Rejected counts.
  • Goal completion — Not Started / In Progress / Completed breakdown with percentages.
  • Charts — department-wise headcount (bar), 6-month leave trends by type (Casual/Sick/Emergency), and monthly hiring trend by joining date.

7.2 Employee Directory /dashboard/employees

The core workforce management module — full CRUD over employee records.

Add / edit employee (multi-tab form)

  • Personal: name, gender, DOB, blood group, marital status, nationality, personal email, father/spouse name, addresses (current/permanent), city/state/PIN, alternate phone, emergency contact & name.
  • Employment: designation, department (Sales, Operations, Marketing, Hiring, Technology, Business Growth), role, reporting manager, work mode (Remote/On-site/Hybrid), employment type (Full-Time/Intern/Contract), date of joining, status (Active/On Leave/Probation/Exited), branch, shift, CTC, notice period, probation end date.
  • Statutory & bank: PAN, Aadhar, PF number, UAN number, bank name, account holder, account number, IFSC.
  • Education: qualification, institution, year of passing, specialisation, skills.
  • Documents: HR-uploaded files (offer letter, internship letter) per employee.

Directory operations

  • Searchable, department-filterable list with profile photo (initials fallback).
  • Auto ID generation and automatic Auth account + credentials on creation (credentials surfaced to HR to share).
  • Bulk import from CSV/Excel with per-row validation and inline error correction.
  • Export the filtered list to spreadsheet.
  • Field validation, e.g. Indian phone numbers (10 digits, starting 6–9).
  • View drawer with tabs (info / employment / documents) and a delete flow with confirmation and error handling.

7.3 Attendance & Time /dashboard/attendance

  • Daily attendance logs per employee with status (Present, Absent, Half Day, Leave, Week Off).
  • Check-in / check-out times and computed working hours.
  • Live clock records and regularisation requests raised by employees for HR review.
  • Filtering by date; roll-up counts feed the dashboard's attendance overview.

7.4 Leave Management /dashboard/leave

  • Real-time queue of leave requests (live listener) with Approve / Reject actions.
  • Each request: employee, leave type (Sick, Casual, Annual, Emergency, Maternity, Paternity), start/end dates, day count, reason, request date, status, approver.
  • Medical-proof attachments viewable/downloadable.
  • Decisions sync instantly back to the employee's Leave page and update dashboard counts.

7.5 Payroll & Compensation /dashboard/payroll · /dashboard/compensation

  • Monthly payroll runs producing per-employee records: basic, allowances, deductions, net salary, payment status (Paid/Pending), payment date.
  • Salary table across the workforce; compensation and incentives management.
  • Generated payslips become available to employees for download.

7.6 Recruitment & ATS /dashboard/recruitment

  • Candidate pipeline with statuses: Applied → Screening → Shortlisted → Interview Scheduled → Interview Completed → Selected / Rejected → Offer Released → Joined.
  • Candidate record: name, contact, role, department, experience, college, LinkedIn, source, recruiter, resume, notes.
  • Move candidates through stages; convert selected candidates toward onboarding.

7.7 Hiring & Sourcing /dashboard/hiring

  • Job postings with title, department, date posted, status (Published/Draft/Closed) and applicant counts.
  • Sourcing channels overview.

7.8 Goals / KPIs & Performance /dashboard/goals · /dashboard/performance

  • Assign goals to employees: goal name, description, KPI, deadline, progress %, status (Not Started / In Progress / Completed), feedback.
  • Goals appear on the employee side in real time; employees update progress, HR reviews.
  • Performance reviews recorded per employee.

7.9 Onboarding /dashboard/onboarding

  • New-hire checklists with tasks (title, due date, completed flag) and overall progress %.
  • Tracks each new employee's ramp-up from joining.

7.10 Documents /dashboard/documents

  • Central repository of employee & HR documents with metadata (category, status, file type, size, uploader).
  • Categories: Identity, Education, Professional, Employment, Financial, Other.

7.11 Reports & Analytics /dashboard/reports

  • Workforce analytics and exportable reports drawn from the live data set.

7.12 Admin & Access Control /dashboard/admin · /dashboard/access

  • Role assignment and access management for administrative control.

7.13 Notifications /dashboard/notifications

  • Compose announcements/alerts with type (leave, attendance, payroll, announcement, interview) and target (all / employee / hr).
  • Delivered to employees in real time with unread badges in their sidebar.

7.14 Help & Support /dashboard/help

  • Inbox of employee-submitted queries (with attachments) for HR to respond to.

7.15 Settings /dashboard/settings

  • Organisation configuration, including the holidays list that drives the employee calendar highlighting.

8. Employee Self-Service Portal — Complete Module Specification

8.1 Personal Dashboard /dashboard

  • Personalised welcome with employee's first name, current date and live clock.
  • Today's attendance status (Present/Absent), clock-in/out and working hours.
  • Leave stats: pending, approved, rejected counts.
  • Employee info strip: ID, designation, department, reporting manager, shift.

8.2 My Profile /dashboard/profile

Tabbed profile: Overview, Personal Details, Employment Details, Documents, Security.

  • Overview: profile photo (upload/preview/remove), name, designation, department, status & employment-type badges, key facts (email, phone, ID, DOJ, manager, work mode).
  • Personal Details: editable name, phone, emergency contact, addresses; Education (degrees, institute, grade, certificate upload), Work Experience, Skills & Languages, and Personal & Government IDs where HR-set fields (DOB, gender, blood group, marital status, nationality, PAN, Aadhar) are shown "By HR" and locked.
  • Employment Details: read-only view of ID, designation, department, type, work mode, DOJ, manager, location, shift, CTC.
  • Documents: predefined slots (PAN, Aadhar, 10th/12th memos, degree, resume, bank proof; offer/internship letters are HR-only) plus extra uploads, with view/download and status.
  • Security: change password (with re-auth) and forgot-password email.
Photo synchronisation: On upload, the photo is stored in Storage and written to the employee record; the URL is broadcast so the sidebar updates instantly, and it also appears in the HR employee directory. The system reads both photoURL and profilePhoto fields for backward compatibility.

8.3 My Attendance /dashboard/attendance

  • Monthly attendance log (own records only) with status and working hours; supports raising regularisation requests.

8.4 My Leave /dashboard/leave

  • Apply for leave (type, date range, reason, optional medical proof).
  • Track requests with live status (Pending → Approved/Rejected) that updates without refresh.
  • Cancel a request while still Pending.

8.5 My Payslip & Compensation /dashboard/payslip · /dashboard/compensation

  • View and download monthly payslips; view personal compensation and incentive records.

8.6 My Goals /dashboard/goals

  • View goals assigned by HR (real-time) and update progress; see KPI, deadline and feedback.

8.7 Calendar /dashboard/calendar

  • Month view opening on the current month; company holidays (from settings) highlighted, and today marked with a ring.

8.8 Notifications /dashboard/notifications

  • Company announcements and personal alerts; unread badge counts in the sidebar; mark-as-read behaviour.

8.9 Help & Support /dashboard/help

  • Raise queries to HR with optional attachments; queries land in the HR help inbox.

11. Real-Time Synchronisation Behaviour

The two dashboards stay consistent because both read/write the same Firestore project. Selected data uses live listeners so changes appear without a manual refresh:

DataSync behaviour
Leave requestsHR approval/rejection updates the employee's Leave page live.
GoalsHR-assigned goals appear for the employee immediately.
NotificationsAnnouncements increment the employee's unread badge in real time.
Sidebar identity/photoLive listener on the employee record; photo uploads broadcast a same-session event for instant update.
Profile editsEmployee changes reflect in the HR directory (on reload of the list / cache refresh).

12. Caching & Performance Design

  • Cache-first reads: lists and identity are cached in sessionStorage and rendered instantly, then refreshed from Firestore in the background (cache-then-network).
  • Skeleton loaders: header, stat-grid, chart and card skeletons prevent layout shift on first load.
  • Automatic invalidation: any create/edit/delete re-runs the loader, which rewrites the cache — so cached data never goes stale.
  • Sidebar caching: employee name and photo restore instantly from cache on reload.

13. Security & Authorization Rules

  • Authentication required for all Firestore and Storage access.
  • Employee data isolation: leave rules restrict employees to records where empId matches their own users/{uid}.employeeId; HR admins (role claim or users-doc role) have full access.
  • Write restrictions: e.g. payroll writes are HR-only; users can only write their own users/{uid} document.
  • Storage rules: photos, documents, certificates and attachments require authentication to read/write.
  • Secrets: Firebase configuration is injected via NEXT_PUBLIC_* environment variables; .env.local files are never committed to source control.

15. Deployment & Infrastructure

  • Build: each app is statically exported (next build → out/).
  • Deploy: firebase deploy --only hosting from the HR dashboard directory releases both hosting targets together.
  • Sites: HR → hrmanagement-6b903.web.app; Employee → woways-employee.web.app.
  • Backend: one Firebase project provides Firestore, Storage and Auth for both apps.
  • Rules: firestore.rules and storage.rules are versioned in the repository and deployed alongside the apps.

16. Assumptions, Constraints & Future Roadmap

Assumptions

  • Single organisation (WOWAYS) on one Firebase project; HR provisions employee accounts.
  • Email/password is the sole authentication method.

Constraints

  • Static export — no server-side rendering or server APIs; all logic is client-side against Firebase.
  • Payroll and statutory features are record-keeping, not a certified compliance/filing engine.

Future roadmap

  • Push/email notifications; biometric or geo-based attendance; native mobile app.
  • Advanced analytics and AI-driven HR insights.
  • Multi-tenant / multi-company support and Single Sign-On (SSO).
  • Automated payslip PDF generation and statutory export packs.
