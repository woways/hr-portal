1. Introduction & Objectives

This document defines the test plan and QA requirements for the WOWAYS HR Portal, which consists of two connected web applications sharing a single Firebase backend — the HR Admin Dashboard and the Employee Self-Service Portal. The objective is to validate functionality, data integrity, real-time synchronisation between the two apps, security (role-based access), performance (cache-first loading) and cross-browser UI behaviour.

Primary quality goal: Any action taken in one dashboard (e.g. HR approving leave, an employee uploading a photo) must be correctly persisted to Firestore/Storage and accurately reflected in the other dashboard, under the correct security constraints.

2. Scope of Testing

In Scope

  • All HR Admin modules: Dashboard, Employees, Attendance, Leave, Payroll/Compensation, Recruitment/Hiring, Goals/Performance, Onboarding, Documents, Reports, Admin/Access, Notifications, Help, Settings.
  • All Employee modules: Dashboard, Profile, Attendance, Leave, Payslip, Goals, Calendar, Notifications, Compensation, Help.
  • Authentication, role-based access, real-time sync, file uploads, caching, responsive UI.

Out of Scope

  • Firebase platform internals (Google-managed infrastructure).
  • Load/stress testing beyond expected organisational scale.
  • Native mobile apps (web-responsive only).

3. Test Strategy & Types

Test TypePurpose
FunctionalVerify each feature behaves per requirements (CRUD, approvals, uploads).
Integration / SyncVerify data written in one app appears correctly in the other via Firestore.
Security / AuthorizationVerify Firestore & Storage rules restrict access to authorised users only.
UI / UsabilityVerify layout, branding, navigation, empty/loading/error states.
PerformanceVerify cache-first render, skeleton loaders, and background refresh.
CompatibilityVerify behaviour across Chrome, Edge, Firefox and tablet widths.
RegressionRe-verify core flows after each deployment.

6. Entry & Exit Criteria

Entry Criteria

  • Both apps deployed to the test/production URLs and reachable.
  • Test accounts and seed data created; Firestore/Storage rules deployed.

Exit Criteria

  • 100% of P1 (critical) test cases pass; no open P1/P2 defects.
  • ≥95% of all test cases pass; remaining issues documented and accepted.
  • Regression suite green on the final build.

16. Regression Checklist & Sign-off

Post-deployment regression (run after every deploy)

  • ☐ HR login & employee login succeed.
  • ☐ Add / edit / delete employee works; directory & KPIs update.
  • ☐ Apply leave → approve → status syncs to employee.
  • ☐ Upload profile photo → shows in sidebar, profile & HR list; persists on reload.
  • ☐ Assign goal & send notification → received by employee.
  • ☐ Cached pages render instantly; refresh brings latest data.
  • ☐ Sidebars show correct navy branding & spacing on both apps.
